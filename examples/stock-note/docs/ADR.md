# Architecture Decision Records

## 철학
MVP 속도 최우선. 외부 계정이나 서비스 없이 서버 한 대에서 동작하게 한다. React Native로 넘어갈 때 버리는 코드를 줄인다. 작동하는 최소 구현을 선택한다.

---

### ADR-001: Next.js App Router를 단일 Node 서버로 실행
**결정**: Next.js 16 App Router로 페이지와 API를 한 프로젝트에 두고, `next start`로 서버 한 대에서 실행한다.
**이유**: 화면과 API를 따로 만들 인력이 없다. SQLite 파일과 crontab을 쓰려면 디스크가 유지되는 서버가 필요하다.
**트레이드오프**: 서버리스 배포(Vercel 등)를 쓸 수 없다. 서버 운영과 백업을 직접 한다.

### ADR-002: SQLite + Prisma
**결정**: 데이터는 SQLite 파일 하나에 저장하고 Prisma로 접근한다.
**이유**: DB 서버나 외부 계정 없이 바로 시작할 수 있다. 피드백 수집 단계의 매장 수에는 충분하다.
**트레이드오프**: 서버를 여러 대로 늘릴 수 없다. 정식 출시 전에 Postgres로 옮겨야 한다. Prisma 스키마의 provider를 바꾸고 데이터를 이전한다.

### ADR-003: 쓰기는 Route Handler로, Server Action은 쓰지 않는다
**결정**: 모든 쓰기는 `app/api/`의 Route Handler가 JSON으로 처리한다. 웹 화면도 같은 API를 호출한다.
**이유**: React Native 앱이 같은 API를 그대로 쓸 수 있다. Server Action은 웹 화면에서만 호출할 수 있다.
**트레이드오프**: 폼마다 fetch 코드와 요청 검증을 직접 쓴다. 읽기용 GET 라우트는 앱을 만들 때 추가해야 한다.

### ADR-004: 사용량은 저장하지 않고 계산한다
**결정**: 사용량 테이블을 두지 않는다. 월말 재고와 입고 기록에서 `lib/usage.ts`의 순수 함수로 매번 계산한다.
**이유**: 점주가 지난 재고나 입고를 고치면 사용량이 따라 바뀌어야 한다. 저장해 두면 원본과 어긋난다. 순수 함수라 테스트하기 쉽고 React Native에서도 그대로 쓴다.
**트레이드오프**: 조회할 때마다 계산한다. 품목이 9개라 부담이 없다.

### ADR-005: iron-session 쿠키 세션 + bcryptjs
**결정**: 아이디·비밀번호를 bcryptjs 해시로 확인하고, iron-session의 암호화된 httpOnly 쿠키에 사용자 id·역할·매장 id를 담는다.
**이유**: 본사가 계정을 발급하므로 가입, 소셜 로그인, 메일 인증이 필요 없다. 인증 프레임워크를 들일 이유가 없다.
**트레이드오프**: React Native 앱은 쿠키 대신 토큰 방식이 필요해 인증 부분을 다시 만든다. 세션을 서버에서 강제로 끊을 수 없다.

### ADR-006: 웹 푸시 + 외부 cron 트리거
**결정**: 알림은 Web Push(VAPID, `web-push`)로 보낸다. 발송 시각은 서버 crontab이 정하고, crontab이 CRON_SECRET으로 보호된 `/api/cron/order-reminder`를 호출한다. 라우트는 오늘이 수·목인지 확인하고 `OrderReminderLog`의 날짜 유일 제약으로 하루 한 번만 보낸다.
**이유**: 외부 알림 서비스 없이 브라우저 표준만으로 된다. 발송 로직이 일반 라우트라 테스트할 수 있고, 서버가 재시작해도 예약이 사라지지 않는다.
**트레이드오프**: iOS는 홈 화면에 추가한 뒤에만 푸시를 받는다. 그래서 발주일에는 홈 배너를 함께 보여준다. crontab 설정은 배포 절차에 따로 넣어야 한다.

### ADR-007: 날짜는 KST 문자열로 저장한다
**결정**: 월은 `YYYY-MM`, 일은 `YYYY-MM-DD` 문자열로 저장한다. 현재 월·일·요일은 `lib/date.ts`가 Asia/Seoul 기준으로 구한다.
**이유**: 매장이 모두 한국에 있다. 서버 시간대가 UTC여도 월말과 발주 요일이 어긋나지 않는다. SQLite에는 날짜 타입이 없다.
**트레이드오프**: 다른 시간대의 매장을 지원하려면 구조를 바꿔야 한다.
